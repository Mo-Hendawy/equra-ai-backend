02 — Agent Descriptions

Each agent is a specialized AI component with a distinct role, tools, and data access pattern.

🎯 Agent Supervisor

The orchestrator. Receives user requests, decomposes them into sub-tasks, dispatches to the right agents, aggregates their results, and sends to Gemini for final synthesis. Manages conversation flow and error recovery.

🔍 Critic Agent

Quality gate. Reviews every response before it reaches the user. Cross-checks financial figures against raw data sources, validates calculations (P/E, fair value, Sharpe ratio), and flags hallucinated or outdated information.

📊 Auditor Agent

Financial statement expert. Reads and interprets annual reports, quarterly earnings, balance sheets, income statements, and cash flow statements. Extracts KPIs like revenue growth, debt ratios, and profit margins.

📡 Real-Time Agent

Market data specialist. Fetches live prices, volumes, historical data via EODHD, TradingView, CNBC, and Mubasher. Manages the data source fallback cascade and maintains the 24h API cache.

🧠 Strategist Agent

Personalization engine. Maintains the investor profile (risk tolerance, goals, budget, sector preferences). Tailors all recommendations to the user's specific situation — not generic advice.

📋 Context Agent

Manages historical context — quarterly revenue analysis, financial sheets over time, sector trends, and macro indicators. Provides temporal depth that real-time data alone cannot offer.

11 — Missing Scenarios & Recommendations

Areas where the architecture could be strengthened.

Missing Scenarios in the Current Design

1. Error Recovery & Graceful Degradation

What happens when Gemini is down? When all price sources fail? The architecture diagram doesn't show error handling flows. Recommendation: Add a fallback path in each sequence diagram showing degraded-but-functional responses.

2. Rate Limiting & Quota Management

No mention of how API rate limits are handled across EODHD, TradingView, Gemini. Recommendation: Add a Rate Limiter component that tracks quotas per source and prioritizes cache when limits are near.

3. User Authentication & Data Security

Portfolio data is sensitive financial information. No auth layer shown. Recommendation: Add JWT/OAuth authentication and encrypted storage for portfolio data.

4. News & Sentiment Analysis

The Real-Time Agent mentions "news" but there's no news feed integration or sentiment analysis pipeline. Recommendation: Add a Sentiment Agent or give the Real-Time Agent news API access (e.g., NewsAPI, company announcements from EGX).

5. Alerting & Notifications

No proactive alerts when a watched stock hits a target price or a held stock drops significantly. Recommendation: Add a Monitoring Agent that runs periodic checks and pushes notifications.

6. Multi-Turn Conversation

The session memory is planned but the flows show single request-response. Recommendation: Design a conversation flow where the user can ask follow-ups like "What about HRHO instead?" without re-stating context.

7. Backtesting & What-If Scenarios

No ability to simulate "What if I had bought COMI 6 months ago?" or "What if the market drops 10%?" Recommendation: Add a Simulation Agent with historical backtesting capabilities.

8. Dividend & Income Projection

Dividend data exists in the mobile app but no projection model. Recommendation: Have the Strategist Agent project future dividend income based on history and payout ratios.

9. Regulatory Compliance

Financial advice has legal implications. No disclaimer system or compliance checks. Recommendation: Add mandatory disclaimers and ensure outputs always state "not financial advice" with confidence levels.

10. Audit Trail & Explainability

No logging of why a recommendation was made. Recommendation: Store the full reasoning chain (which agents contributed, what data was used) for every recommendation.

Architecture Strengths

What's Good About the Design:
  • Separation of Concerns: Each agent has a clear, focused responsibility — this scales well.
  • Critic Agent: Having a validation layer before user-facing output is excellent for financial applications where accuracy matters.
  • Parallel Execution: Agents can gather data simultaneously, reducing latency.
  • Personalization via Strategist: Most robo-advisors give generic advice — the Strategist Agent differentiates Equra AI.
  • Data Source Redundancy: The fallback cascade for price data is production-ready and resilient.

12 — Lessons Learned (So Far)

Building an AI-powered financial assistant for an emerging market taught us things no tutorial could. Here are the honest takeaways.

1. Start Monolithic, Earn Your Agents

We didn't start with a multi-agent system — and that was the right call. Our first version was a single Express API making direct Gemini calls with different prompts. It worked. It shipped. Users gave feedback. Only after we understood the real failure modes — hallucinated P/E ratios, stale prices, generic advice — did the agent architecture become obvious. Each agent exists because a real problem demanded it, not because an architecture diagram looked cool.

2. Financial Data is a Mess (Especially in Emerging Markets)

In the US, you call one API and get clean data. In the Egyptian market (EGX), no single source is reliable. EODHD has gaps. TradingView blocks you. CNBC is delayed. Mubasher changes its API. We built a four-layer fallback cascade not because we wanted to — because we had to. If you're building for any market outside the US/EU, budget 3x the time you think you'll need for data ingestion.

3. The Critic Agent is Not Optional for Finance

LLMs hallucinate. That's a known fact. But when an LLM tells someone a stock's P/E is 5 when it's actually 50, that's not a quirky mistake — it's a financial decision made on false data. The Critic Agent isn't a nice-to-have. It's the difference between a toy project and something people can actually trust with their money.

4. Cache Everything, Trust Nothing

Our 24-hour file cache with stale fallback has saved us countless times. APIs go down at the worst moments. Rate limits hit mid-analysis. The lesson: always return something useful. A slightly stale price with a warning is infinitely better than a loading spinner that never resolves.

5. Personalization is the Moat

Every finance app can show you a stock's P/E ratio. The thing that makes users come back is when the system says "Based on your portfolio being 40% banking sector, adding COMI would increase your concentration risk — consider SWDY instead." Generic analysis is a commodity. Personalized analysis is a product.

6. Prompts Are Your Agent Logic (For Now)

Before you reach for LangGraph or CrewAI, consider this: our entire "multi-agent" behavior started as different system prompts on the same model. The Auditor prompt focuses on financials. The Strategist prompt gets the user's portfolio context. This works surprisingly well and is far easier to debug than a real agent framework. Graduate to proper agents when prompt-switching becomes a bottleneck — not before.
