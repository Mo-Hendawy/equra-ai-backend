Overview

System Architecture — How Everything Connects

Equra AI is not a single AI call wrapped in an app. The mobile app directly calls purpose-built endpoints — each screen and component knows exactly which API to hit. There is no server-side orchestrator: routes.ts registers Express handlers, and the mobile UI decides what to call based on user action. This section shows how all 7 features connect as one system.

Feature 01

Multi-Agent AI System

"Built and orchestrated a multi-agent AI system with dedicated agents: Portfolio Health Check, Stock Comparison, Capital Deployment, Behavior Coaching, Transaction Import, and Manus AI Deep Analysis"

Product — When is each agent used?

  • Portfolio Analysis Agent — user opens portfolio screen, wants health check, diversification score, strengths/weaknesses
  • Stock Comparison Agent — user picks 2–3 stocks and asks "which should I buy with X EGP"
  • Capital Deployment Agent — user has cash to invest and wants AI to allocate across their existing portfolio
  • Behavior Coaching Agent — user wants feedback on their trading patterns and habits
  • Transaction Import Agent — user screenshots their brokerage statement; Vision extracts transactions as JSON
  • Manus AI Agent — user requests deep autonomous research on a specific stock; runs async in background

Engineering — How routing works

The mobile app calls each endpoint directly — no server-side orchestrator. routes.ts registers Express handlers; the mobile UI decides which endpoint to call based on which screen or component is active:

  • GET /api/ai/:provider/stock-analysis/:symbol — Stock Analysis (StockAnalysis component)
  • POST /api/ai/:provider/portfolio-analysis — Portfolio Agent (AIScreen)
  • POST /api/ai/:provider/deploy-capital — Capital Deployment Agent (AIScreen)
  • POST /api/ai/:provider/compare-stocks — Stock Comparison Agent (AIScreen)
  • POST /api/ai/:provider/behavior-analysis — Behavior Agent (AIScreen)
  • POST /api/extract-transactions — Vision Agent (TransactionImportModal)
  • POST /api/manus/analyze/:symbol — Manus AI Agent (ManusDeepAnalysis component)

Each handler calls runAnalysis(provider, type, data) in ai-providers.ts with a different type that selects the prompt builder and Zod schema.

Feature 02

Hybrid RAG Pipeline

"Designed a hybrid RAG pipeline combining query expansion, Reciprocal Rank Fusion (RRF), and keyword re-ranking over financial PDF embeddings stored in LanceDB"

Product — Why does this exist?

Company financial reports (PDFs) contain the ground-truth data the AI needs — actual revenue, margins, earnings, guidance. Without RAG, the AI relies on training data which may be months or years out of date. RAG injects the real numbers directly into the prompt.

A user asks "should I buy ABUK?" — RAG pulls the latest quarterly earnings chunks so Gemini can say "revenue grew 25% YoY per their Q3 report" instead of guessing.

Engineering — The 4 components

  • Query Expansion — expandQuery(symbol, taskType) in rag/query-expansion.ts generates 4 hardcoded query variants targeting different financial angles
  • Vector Search — each variant searches LanceDB table financial_reports_{symbol}, returns top 8 chunks by embedding similarity
  • RRF Merge — mergeAndRerank() in rag/hybrid-retrieval.ts: score = Σ 1/(60 + rank), combines ranked lists from all query variants
  • Keyword Re-rank — term overlap scoring with stopwords removed, final score = 70% RRF + 30% keyword overlap

Controlled by RAG_HYBRID_ENABLED env var

If false, falls back to simple vector-only search: one query, one LanceDB call, top 6 by similarity. No RRF, no keyword re-rank. Useful when embedding API is rate-limited.

Feature 03

Chain-of-Thought Prompting

"Implemented Chain-of-Thought prompting with structured reasoning steps (data check, valuation, zone derivation, risk assessment, recommendation), surfaced transparently in the mobile UI"

Product — Why does this exist?

Without CoT, the AI produces a recommendation with no visible reasoning. Users don't know why it says "Strong Buy". With CoT, every step of the AI's logic is shown in an expandable card in the mobile UI — users can see exactly which data was used and how the conclusion was reached.

A user seeing "Step 2: Graham formula gives fair value 47 EGP, current price 32 EGP = 32% discount" is far more likely to act on the recommendation than one who just sees "Strong Buy".

Engineering — How it works

The CoT is not 5 separate API calls. It is one prompt that instructs the LLM to reason step by step before producing the final JSON. All 5 reasoning steps happen inside a single LLM call and are returned in the reasoningSteps[] array.

Each provider is called in parallel from the mobile. The validation loop in runAnalysis retries up to 2 times — on each retry, the specific schema or parse error is appended to the prompt so the LLM can self-correct.

Mobile UI: StockAnalysis.tsx renders each provider result as a card with a "How we got here" expandable section. Tapping it shows reasoningSteps[] as a numbered list. Results are cached in AsyncStorage.

What is assembled BEFORE the single LLM call

  • Price: EODHD → TradingView → CNBC → stale cache (fallback chain)
  • Fundamentals: TradingView → Mubasher → EGX static cache
  • Risk metrics: 252-day EODHD historical prices → Sharpe ratio, Sortino ratio, priceChange30d, priceChange90d (all calculated in backend)
  • RAG context: 4 query variants → LanceDB vector search (8 candidates each) → RRF + keyword rerank → top 6 chunks from financial PDF reports
  • FinBERT: Raw per-headline scores — { title, source, scores: [{label, score}] } — not aggregated

Feature 04

FinBERT Financial Sentiment Analysis

"Integrated FinBERT for real-time financial sentiment analysis, injecting raw per-headline scores directly into LLM reasoning context"

Product — What does it do?

For every stock analysis, the app fetches recent news headlines — company-specific and Egypt macroeconomic. Each headline is scored by FinBERT, a BERT model fine-tuned on financial text, returning a probability for positive, negative, and neutral sentiment.

These scores are injected raw into the LLM prompt. Gemini sees each headline with its exact scores and factors this into the risk assessment and recommendation steps.

Engineering — Two output modes

Raw — sent to AI: Per-headline scores array. Each item is { title, source, scores: [{label, score}] }. No aggregation. The LLM sees every individual score.

Aggregated — displayed in UI: Average bullish/bearish/neutral scores. Label is "Bullish" if avgBullish is above 0.40 and greater than avgBearish, "Bearish" if opposite, else "Neutral".

News sources: EODHD news API with fallback to Google News RSS for company news, and BBC RSS feeds for macro Egypt news.

Feature 05

Multi-Provider LLM Orchestration

"Built a multi-provider LLM orchestration layer (Gemini, Groq, Cerebras, HuggingFace) with automatic fallback chains and exponential-backoff retry logic"

Product — Why multiple providers?

Each provider has rate limits, quota caps, and different response quality. The AI Screen lets users compare all 4 providers side by side for the same stock. If one provider is rate-limited or down, analysis continues through the others.

Users can see how Gemini, Groq Llama 4, Cerebras 120B, and HuggingFace Qwen 2.5 each reason about the same stock — different models, same structured output format.

Engineering — Provider config

  • Gemini 2.5 Pro — callGemini() via Google Generative AI SDK, lazy-loaded client
  • Groq Llama 4 — model meta-llama/llama-4-scout-17b-16e-instruct, OpenAI-compatible at api.groq.com/openai/v1
  • Cerebras 120B — model gpt-oss-120b, OpenAI-compatible at api.cerebras.ai/v1
  • HuggingFace Qwen 2.5 — model Qwen/Qwen2.5-72B-Instruct, OpenAI-compatible at router.huggingface.co/v1

Retry: 3 attempts, exponential backoff 2s then 4s then 8s on 429 and 503. Status 402 skips immediately. JSON parse failures and Zod failures trigger self-correction retry with error feedback appended to prompt.

Feature 06

Manus AI Autonomous Agent

"Integrated Manus AI as an autonomous web agent via asynchronous webhooks to perform deep-dive research and generate comprehensive financial reports"

Product — What does it do?

When a user requests a deep dive on a stock, Manus AI takes over autonomously. It browses the web on its own — finds EGX filings, financial news, analyst reports — and produces a comprehensive Markdown research report including: company overview, financial analysis, competitive landscape, macroeconomic factors, DCF valuation, fair value zones, and risk assessment.

This is async — the user sees "analysis in progress" while Manus works in the background. Results are cached for 24 hours.

Engineering — The async webhook flow

  • Initiation: POST /api/manus/analyze/:symbol calls Manus API /v1/tasks with agentProfile "manus-1.6" and taskMode "agent". Returns taskId immediately.
  • Polling: GET /api/manus/status/:symbol polls Manus /v1/tasks/:taskId for real-time status.
  • Webhook: Manus calls POST /api/manus/webhook on task.completed. Handler extracts symbol via regex from task output.
  • Extraction: extractManusOutput() filters for role="assistant" messages, extracts type="output_text" content.
  • Parsing: parseManusReport() uses regex to extract summary, recommendation, and fair value from Markdown.

Feature 07

Resilient AI Pipelines

"Engineered resilient AI pipelines with graceful degradation across price sources (EODHD, TradingView, CNBC), news feeds, and LLM providers"

Product — Why does this matter?

EGX data is not on Bloomberg. EODHD is the primary source but has quota limits. TradingView has no official API. CNBC has scraped endpoints. Any of these can fail at any time.

Without resilience, a single EODHD rate-limit would break every stock card. With the fallback chain, the app degrades gracefully. The response includes a priceSource field so the UI shows "data from TradingView" when EODHD is unavailable.

Engineering — Three fallback chains

Price: EODHD EOD → TradingView scan endpoint → CNBC quote endpoint → stale cache

Fundamentals: TradingView (EPS, P/E, P/B) → Mubasher overview → EGX static cache (70+ stocks, Jan 2026 snapshot)

News: EODHD news → Google News RSS for company news, BBC RSS for macro Egypt news

LLM: All providers fail after retries → formula fallback using P/E + Graham formula, returns confidence=Low
