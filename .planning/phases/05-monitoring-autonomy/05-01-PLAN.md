    2. Create `server/monitoring/monitoring-bus.ts`:

    Define `AlertType` union: `'PRICE_MOVE' | 'SENTIMENT_SPIKE' | 'EARNINGS' | 'CBE_EMERGENCY'`

    Define `AlertPriority` record mapping each type to a number (higher = more urgent):
    - CBE_EMERGENCY: 4
    - EARNINGS: 3
    - SENTIMENT_SPIKE: 2
    - PRICE_MOVE: 1

    Define `AlertEvent` interface:
    ```
    { symbol: string; type: AlertType; priority: number; triggeredAt: Date; metadata?: Record<string, unknown> }
    ```

    Create `MonitoringBus` class extending `EventEmitter`. Internal state:
    - `cooldownMap: Map<string, Date>` — key is `${symbol}:${type}`, value is when cooldown expires

    Method `canAlert(symbol, type): boolean` — returns false if `cooldownMap` has a non-expired entry for `${symbol}:${type}` (24-hour window per pitfall L3).

    Method `scheduleAlert(event: AlertEvent): void`:
    - Call `canAlert`. If false, log `[monitoring-bus] cooldown active for ${event.symbol}:${event.type} — skipping` and return.
    - Set cooldown: `cooldownMap.set(key, new Date(Date.now() + 24 * 60 * 60 * 1000))`
    - Emit `'alert'` with the event.

    Method `onAlert(handler: (event: AlertEvent) => void): void` — registers the handler on `'alert'` event. This is the subscription point for the orchestrator trigger.

    Export `monitoringBus = new MonitoringBus()`.

    In the same file, wire the orchestrator trigger as a side effect (import orchestrator, call `monitoringBus.onAlert(async (event) => { ... })`). Inside the handler: log `[monitoring-bus] triggering re-analysis for ${event.symbol} type=${event.type} priority=${event.priority}`, then call `orchestrator.run(...)` with null-safe price/financials (all nulls are fine — DataAgent fetches fresh data). Fire-and-forget with `.catch(e => console.error(...))`. Do NOT await — alert handler must not block.
  </action>

    **server/monitoring/price-monitor.ts — MON-01, M2 volume gate, C5 data hazard:**

    Export `startPriceMonitor(): void`.

    Internal `volumeBaseline: Map<string, number>` — stores 30d average volume per symbol (computed on first run from last 30 days of EODHD data).

    Internal `lastPrices: Map<string, number>` — stores last seen close price per symbol.

    On startup: read `WATCHLIST_SYMBOLS` env var (comma-separated, e.g. `COMI,HRHO,FWRY`). If unset, use fallback: `['COMI', 'HRHO', 'FWRY', 'CANA', 'HDBK']`.

    Schedule via `node-cron` with `cron.schedule('*/15 * * * *', pollFn, { timezone: 'Africa/Cairo', name: 'price-monitor' })`.

    In `pollFn`:
    - For each symbol, fetch latest EODHD EOD data (last 31 days, `order=d`).
    - Extract current close and current volume from `data[0]`.
    - Compute `avg30dVolume` from `data.slice(1, 31)` — average of `.volume` field (parse as float, skip nulls/zeros). Store in `volumeBaseline`.
    - Compute `changePercent = Math.abs((currentClose - lastPrices.get(symbol)) / lastPrices.get(symbol)) * 100`.
    - If `lastPrices` has no entry for this symbol, store price and continue (baseline only).
    - **M2 volume gate (pitfall):** Only trigger if `currentVolume >= 0.5 * avg30dVolume`. If volume is too thin, log `[price-monitor] ${symbol} move ${changePercent.toFixed(1)}% ignored — thin volume (${currentVolume} < 50% of ${avg30dVolume.toFixed(0)})` and skip.
    - If `changePercent >= 5` AND volume gate passes: call `monitoringBus.scheduleAlert({ symbol, type: 'PRICE_MOVE', priority: AlertPriority.PRICE_MOVE, triggeredAt: new Date(), metadata: { changePercent, currentVolume, avg30dVolume } })`.
    - Update `lastPrices.set(symbol, currentClose)`.
    - Wrap per-symbol logic in try/catch — one failure must not abort the poll for other symbols.
